dist[node]

從起點到這個節點，目前已知的最低總成本。初始值是無限大，起點是 0。

parent[node]

當距離變得更短時，記錄是從哪個節點走過來，最後可以回溯一條最短路徑。

PriorityQueue

每次優先取出成本最低的待處理項目，不是單純先進先出。

先背這一份，遇到不同題目主要改「建圖方式」和「最後輸出」。可單起點，也可用 params 多起點。

重要限制：Dijkstra 僅能保證非負邊權下的正確最短距離。若題目有負權邊、要求最長路徑或列舉所有路徑，不能直接套。
逐段拆解
① params int[] starts 是什麼？
允許呼叫 Dijkstra(graph, 0) 或 Dijkstra(graph, 0, 3, 5)。函式裡的 starts 仍然是整數陣列。若只要單起點，可以改成普通 int start。
② graph 裡到底存什麼？
List<(int to, long cost)>[] 是鄰接串列。graph[u] 存從 u 出發能走到哪裡，以及每條邊的成本。例如 graph[0].Add((2, 7)) 代表 0 → 2 成本 7。
③ 為什麼 dist 初始化為 long.MaxValue？
表示目前還不知道有沒有路能到達該節點；只有起點為 0。演算法完成後，仍為最大值就代表不可達。
④ 為什麼用 PriorityQueue<int,long>？
第一個型別是存的節點，第二個是排序的優先權（成本）。Dijkstra 必須優先展開成本最低的項目，才有非負權最短路徑的保證。
⑤ currentCost != dist[current] 有何用途？
優先佇列可能同時包含某節點的舊成本 12 和新成本 5。當成本 12 的舊項目之後被取出，這一行可直接略過，避免重複展開。
⑥ newCost < dist[next] 為什麼是核心？
這叫鬆弛（relaxation）。只有找到更短路徑，才更新距離與 parent。相等時不更新，因此可回溯其中一條最短路徑，但不保證指定的同分順序。
⑦ BuildPath 怎麼回溯？
從終點沿著 parent[target]、parent[parent[target]] 不斷往回走，直到起點，再 Reverse() 反轉。多起點時要判斷回溯抵達哪個起點，不能直接套固定單起點函式。


八種題型，怎麼改模板？
點開想練的變形；所有程式都與「完整 C# 核心」搭配。以下 graph 範例的節點是 0-based。
考場判斷口訣：每一步成本相同 → BFS 較有效率；成本不同且都非負 → Dijkstra；只能右／下的網格 → 優先考慮 DP。DFS 不一定慢，但不適合用暴力列舉路徑求一般最短路徑。
